# Srv — персональный сервер CLI-ассистентов

**Уже установлен сервер? Начните с [START-HERE.md](START-HERE.md): подключение
к серверу, возврат в Codex/tmux и работа с файлами.**

В примерах `SERVER_IP` означает IP или DNS-имя вашего сервера. Замените его своим
значением, а `C:\git\Srv` — каталогом распакованного комплекта на вашем компьютере.

Развёртывание Claude Code и Codex на отдельном Ubuntu-сервере сотрудника.
Клиентская машина — Windows или Ubuntu. Общий launcher написан на Python 3.9+
и использует системный OpenSSH; WSL для запуска с Windows не требуется.

Реализованы создание SSH-ключа, первичный вход root по паролю, рабочий пользователь,
установка выбранного агента, запуск в tmux, прямой файловый доступ и двусторонняя
синхронизация. Пилот Codex прошёл личную авторизацию и задание сотрудника;
после разрыва SSH сохранились сессия и процесс окна tmux.

Для Claude Code подготовлен отдельный адаптер установки и запуска; его личная
авторизация в пилотной проверке не проверялась. Импорт и активация готового WireGuard-конфига
ожидают самого файла; параметры существующих Docker/VPN/DNS-сервисов сохраняются.

## Запуск

В обычном интерактивном терминале Windows:

```powershell
python C:\git\Srv\srv.py setup --host SERVER_IP
```

На Ubuntu, из каталога копии проекта:

```bash
python3 srv.py setup --host SERVER_IP
```

Передаваемый комплект собирается `python tools/package.py` в `dist/srv-deployer.zip`.
В архив входят только перечисленные исходники, инструкция и тесты; `.local`,
ключи, тестовые данные и профили машин не включаются. Соседний файл содержит SHA256.

Для нестандартного SSH-порта добавьте `--port 2222`. По умолчанию порт `22`;
он применяется к первичному входу, проверкам и подключению к агенту.
Пользователь сервера по умолчанию `ai-agent`; для другого имени есть `--user`.
UID выбирается из диапазона 20000–20999 с исключением занятых учётными записями
и работающими процессами значений, включая процессы контейнеров.

Агент по умолчанию — Codex. Для другого сотрудника:

```text
python srv.py setup --host SERVER_IP --agent claude
python srv.py agent-install --host SERVER_IP --agent claude
python srv.py connect --host SERVER_IP --agent claude
```

`agent-install` добавляет выбранный CLI существующему рабочему пользователю.
Сессии tmux называются `codex` и `claude`, их личные авторизации независимы.

## Локальная памятка сервера

При запуске launcher автоматически создаёт в `.local/server-guides/`:

- `HOST_PORT_USER-AGENT.md` — готовые команды с адресом, портом, пользователем,
  выбранным агентом, путём SSH-ключа и профилем; пути файлового моста и состояние шагов.
- `HOST_PORT_USER.credentials.md` — отдельный файл для личных учётных данных
  и заметок. При повторном запуске он сохраняется без перезаписи.

Путь памятки выводится до подключения к серверу. Она обновляется после завершения
операции, включая ошибку, и перед входом в агент при `setup`. Можно создать её
отдельно, без SSH и изменения сервера:

```text
python srv.py guide --host SERVER_IP --port 2222 --user ai-agent --agent codex
```

При использовании своих `--identity`, `--state-dir` и `--folder` передайте их
также команде `guide`. Файлы всегда находятся в `.local/server-guides/` проекта,
даже с другим `--state-dir`; для разных серверов/портов и пользователей они отдельные.
Команды в памятке рассчитаны на ОС компьютера, где её сгенерировали.

Новый рабочий пользователь получает доступ по SSH-ключу; пароль ему не назначается.
Пароли существующих аккаунтов не меняются. Пароль root и парольная фраза ключа
вводятся в OpenSSH и автоматически в файлы не попадают; при необходимости
добавьте их вручную в `.credentials.md`. Содержимое личного файла не выводится
и не включается в отчёты. На Unix каталог имеет права 700, файлы — 600;
на Windows действуют права вашего пользовательского профиля/каталога проекта.
`.local/`, каталоги `server-guides/` и `*.credentials.md` исключены через
`.gitignore`. Локальные файлы не входят в ZIP по списку разрешённых файлов.

Скрипт предложит задать парольную фразу SSH-ключа, подтвердить ключ хоста
и ввести выданный root-пароль. Пароли вводятся только в запросах OpenSSH,
не сохраняются и не передаются аргументами. Если ssh-agent не используется,
парольная фраза ключа может запрашиваться при каждом новом SSH-соединении.
Существующие ключи не перезаписываются.

После переустановки сервера SSH может обнаружить смену ключа хоста.
Скрипт не принимает такую смену молча. После проверки отпечатка или явного
подтверждения переустановки можно повторить запуск с параметром:

```text
--trust-host-fingerprint SHA256:ПОДТВЕРЖДЁННЫЙ_ОТПЕЧАТОК
```

Сначала скрипт получает публичный ключ без парольной авторизации и сверяет
отпечаток; затем сохраняет резервную копию known_hosts и заменяет запись только
этого адреса/порта. При несовпадении файла known_hosts не касается.
На переустановленном хосте прежние отметки завершённой установки сбрасываются,
но клиентский ключ остаётся прежним. Для Windows предусмотрен резервный способ
получения ключа при несовместимости алгоритмов в ssh-keyscan.

Ключ по умолчанию хранится в домашнем каталоге сотрудника:
`~/.ssh/srv_SERVER_IP_PORT_ed25519`, публичная часть — соседний файл `.pub`.
Точный путь для выбранного сервера указан в локальной памятке.

Личный вход Codex выполняется в tmux через device code: сотрудник открывает
показанный адрес в своём браузере и авторизуется личной подпиской ChatGPT.
Коды и вывод авторизации launcher не записывает. При недоступности device code
потребуется отдельный вход с SSH-переадресацией callback; это не обходится
копированием авторизации другого сотрудника.

## Отдельные операции

```powershell
python C:\git\Srv\srv.py keygen --host SERVER_IP
python C:\git\Srv\srv.py enroll --host SERVER_IP
python C:\git\Srv\srv.py doctor --host SERVER_IP
python C:\git\Srv\srv.py bootstrap --host SERVER_IP
python C:\git\Srv\srv.py connect --host SERVER_IP
python C:\git\Srv\srv.py verify --host SERVER_IP
```

`doctor` — чтение информации с сервера через root-ключ. `bootstrap` создаёт
рабочего пользователя, устанавливает пакеты и Codex. `setup` выполняет всю
последовательность и затем подключает сотрудника к tmux.

Отсоединиться от tmux: **Ctrl+B, затем D**. `connect` возвращает в сессию `codex`.
Обёртки Codex и Claude включают мышь tmux при каждом подключении для прокрутки
колёсиком. Обновление существующей установки и клавиши просмотра истории —
в [памятке](START-HERE.md#прокрутка-в-windows-terminal-и-tmux).
После отсоединения `setup` проверяет наличие авторизации и живой tmux-сессии.
Эта проверка сама по себе не подтверждает успешный ответ модели:
приёмка включает личное задание сотрудника в Codex.

При ошибке launcher останавливается, не повторяет пароль автоматически.
Повторный `setup` использует существующую пару ключей и пропускает первоначальный
парольный вход, если ключевой вход уже был проверен. Остальные шаги проверяются
повторно; завершённые данные и рабочие каталоги не удаляются.

`setup --wg-config PATH` или отдельный `vpn-stage --wg-config PATH` принимают
готовую конфигурацию: проверяют форму ключей, передают файл по SCP в закрытый
root-каталог и выполняют предварительную проверку без вывода ключей.
Конфигурация сохраняется как `/root/.local/share/srv/wireguard/wg-srv.conf`.
**VPN не активируется:** для следующего этапа нужны сам файл, проверка маршрутов,
DNS и автоматический откат. Автоматическое поднятие и откат ещё не реализованы:
их нужно добавить и проверить по реальному конфигу. В пилотной проверке файла пока нет, staging ещё не прогонялся
с реальной конфигурацией. Без параметра устанавливаются только инструменты VPN.

Пример расположения готового файла вне экспорта:

```powershell
python C:\git\Srv\srv.py vpn-stage --host SERVER_IP --wg-config C:\git\Srv\.local\wg-srv.conf
```

## Состояние и восстановление

`.local/` содержит локальный профиль и события шагов, без вывода терминала,
паролей и содержимого ключей. Эта папка исключена из Git.
Приватные ключи и VPN-конфиги в проект не копируются.

Первый bootstrap не изменяет настройки SSH, firewall или маршруты;
root-доступ по паролю и ключу сохраняется. Рабочему пользователю не выдаётся sudo.
Перезагрузка сервера завершит живой процесс tmux: восстановление чата после
reboot выполняется отдельно средствами Codex.

## Локальные файлы

```powershell
python C:\git\Srv\srv.py files-add --host SERVER_IP --folder C:\git\Srv --mode both --read-write --watch
```

Файловый процесс должен оставаться запущенным на компьютере сотрудника.
Он скачивает rclone 1.76.0 для своей ОС в `.local/bin`, сверяет SHA256 и создаёт
отдельный служебный ключ, ограниченный SFTP на сервере. Личный приватный ключ
сотрудника на сервер не копируется. rclone устанавливается без изменения PATH
и без доступа к другим конфигурациям rclone, например Google Drive.

После успешного `files-add` доступны два разных пути:

- Прямой доступ: `/home/ai-agent/workspaces/live/FOLDER_ID`.
- Серверная копия: `/home/ai-agent/workspaces/sync/FOLDER_ID`.

`FOLDER_ID` вычисляется из выбранной локальной папки. Точные пути печатает
`files-add`; они также включены в локальную памятку при переданном `--folder`.

Прямой доступ идёт через локальный SFTP на 127.0.0.1, обратный SSH-туннель
и sshfs; входящий порт компьютера открывать не требуется. Запись явно разрешает
`--read-write`. Для чтения: `--mode live` без этого флага.
`--remote-file-port` меняет серверный loopback-порт, по умолчанию 22022;
для нескольких одновременных live-каталогов нужны разные порты.

`--mode sync` создаёт только серверную копию, `--mode live` — только прямой доступ.
Добавление нового каталога в режиме sync/both запускает первичную синхронизацию.
Перед ней проверяются место на сервере, объём и приблизительное время по
небольшой пробной передаче. Прогноз свыше 120 секунд требует подтверждения
или явного `--allow-large`. Оценка консервативна и включает накладные расходы.

`--watch` повторяет двустороннюю синхронизацию; интервал задаёт `--sync-interval`
(по умолчанию 15 секунд между завершёнными циклами). Изменения распространяются
в обе стороны. До применения выполняется dry-run: конфликтующие правки
останавливают цикл до перезаписи; если конфликт возник между проверкой и
копированием, rclone сохраняет обе версии с суффиксом `srv-conflict`.
Удаления автоматически не распространяются. При ошибке автосинхронизация
приостанавливается, прямой доступ продолжает работать.

Из обоих режимов исключены `.local`, `.scratch`, `.git`, `.venv` в корне выбранной
папки и `__pycache__`. Ключи, кэш и состояние соединения не экспортируются;
символические ссылки не включаются. Состояние Git не синхронизируется:
репозитории клонируются отдельно и связываются через Git.

У одного файлового процесса может быть только один экземпляр на каталог.
Остановка после текущей операции:

```powershell
python C:\git\Srv\srv.py files-stop --host SERVER_IP --folder C:\git\Srv
```

Также можно нажать Ctrl+C в файловом окне. Серверная копия и Codex остаются.
При отключении компьютера live-доступ перестаёт быть доступным, а серверная
копия остаётся рабочей; пути не подменяются друг другом.

Однократный дополнительный цикл после остановки файлового процесса:

```powershell
python C:\git\Srv\srv.py files-sync --host SERVER_IP --folder C:\git\Srv --read-write
```

При конфликтах сначала сохранить/объединить обе версии и восстановить согласованное
состояние. Автоматический `--resync` поверх существующих файлов не выполняется.
Не запускайте голый `rclone sync`: эта команда может удалять файлы назначения.

## Git-доступ

```powershell
python C:\git\Srv\srv.py git-key --host SERVER_IP
```

Команда создаёт отдельный Git-ключ в `/home/ai-agent/.ssh/id_ed25519` и показывает
только публичную часть. Её нужно зарегистрировать в личном GitHub и внутреннем
Git-сервисе с правами нужных репозиториев. Приватная часть остаётся на сервере.
Публичная часть выводится командой `git-key`.
При bootstrap имя/email автора берутся из локальной глобальной конфигурации Git
и заполняют отсутствующие поля серверного профиля. Для явного задания доступны
`--git-name` и `--git-email` вместе; отдельная операция — `git-identity`.
Если локальный Git не настроен, значения не выдумываются: сотрудник задаёт их
сам или передаёт флагами. Существующая серверная identity без явных флагов сохраняется.

В пилотной проверке проверены clone, push и revert в отдельной ветке AI-Memory.
После проверки временная ветка удалена, основная ветка не менялась.
Внутренние репозитории проверяются после получения VPN-конфигурации.
