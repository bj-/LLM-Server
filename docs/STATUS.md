## Следующие шаги

Инструкции обезличены: адрес сервера обозначен `SERVER_IP`, идентификатор папки —
`FOLDER_ID`. Launcher автоматически создаёт `.local/server-guides/` с точными
командами выбранного профиля и отдельным неперезаписываемым файлом личных данных.
Есть автономная команда `guide`; локальные файлы исключены из Git и ZIP,
а `.gitignore` включён в комплект. Пароли рабочим аккаунтам не назначаются.

Исправлена прокрутка в SSH/tmux: обёртки обоих агентов включают `mouse on`
при подключении. Для ранее установленного сервера нужен `agent-install`, затем
`connect`; работающий агент сохраняется. Подробности — в `START-HERE.md`.

- Получить локальный путь к готовому WG-конфигу (вне экспортируемых папок, например в .local).
- Проверить реальные подсети, DNS и влияние на существующие службы; добавить и проверить активацию с автоматическим откатом.
- Проверить внутренний Git через VPN на предоставленном репозитории и тестовой ветке.
- При выборе Claude сотрудником проверить установку и личный вход на его сервере.

## Блокеры и ограничения

- Файл WireGuard пока не предоставлен. Staging предусмотрен и проверен модульно;
  фактический импорт с реальным файлом не прогонялся; автоматическая активация и откат ещё не реализованы.
- Внутренний Git-сервер/репозиторий для проверки ещё не указан.
- Прямой доступ зависит от работающего клиентского файлового процесса; при его
  отключении серверная копия остаётся. Удаления и конфликтующие правки не распространяются молча.
- Автопроверка отклонила удаление тестовой junction: blocked by policy, без уточнения.
  C:\work\LLM-Server\.file-checks\junction-outside оставлена; .file-checks исключена из Git и передаваемого ZIP.

## Проверенные параметры и восстановление

- Сервер SERVER_IP:22: Ubuntu 24.04 x86_64, пример целевой конфигурации: 4 CPU, 6 ГБ RAM, диск 100 ГБ.
- Входной ключ клиента: %USERPROFILE%\.ssh\srv_SERVER_IP_22_ed25519.
- Рабочий пользователь ai-agent: UID/GID из диапазона 20000–20999, без sudo/Docker-групп.
  UID первоначального пользователя совпал с UID процесса контейнера; вход отключён, ключ установки удалён,
  контейнер не останавливался. Новые UID выбираются с учётом passwd и /proc.
- Существующие Docker, VPN и DNS-службы сохраняются по указанию пользователя.
  Их настройки, firewall и маршруты не менялись. Доступ к серверу только SSH;
  root-вход по ключу и первоначальный парольный доступ сохранены.
- Переустановка сервера подтверждена пользователем; принят Ed25519
  SHA256:HOST_KEY_FINGERPRINT с копией known_hosts.
  Несовместимость Windows ssh-keyscan закрыта безопасным probe без учётных данных.
- Сессия tmux, её панель и процесс Codex сохранились при разрыве SSH.
- Live: /home/ai-agent/workspaces/live/PROJECT-FOLDER_ID.
  Копия: /home/ai-agent/workspaces/sync/PROJECT-FOLDER_ID.
  Состояние и ключи файлового процесса — .local; исключены из экспорта.
- В тестовом репозитории проверены clone, push во временную ветку и откат. Временная ветка удалена с origin. Основная ветка и дерево сохранились, рабочий каталог остался чистым.
- Ручной путь: docs/RUNBOOK.md. Передаваемый комплект: dist/srv-deployer.zip, без .local/ключей/профилей.
