# Как пользоваться готовым сервером

В примерах замените `SERVER_IP` IP-адресом или DNS-именем своего сервера,
`C:\git\Srv` — каталогом комплекта. Значения по умолчанию: SSH-порт `22`,
пользователь `ai-agent`, агент `codex`. Свои значения передавайте через
`--port`, `--user`, `--agent` и при необходимости `--identity`.

Готовые команды с вашими параметрами launcher сохраняет в `.local/server-guides/`.
Путь выводится при запуске. Рядом находится файл `.credentials.md` для личных
данных и заметок; повторный запуск его не перезаписывает. Эти файлы исключены
из Git и передаваемого ZIP. Для создания памятки без подключения:

```powershell
python C:\git\Srv\srv.py guide --host SERVER_IP
```

Инструкция ниже предполагает, что сервер уже подготовлен через `setup`.
Для обычной работы используйте `connect`; повторное развёртывание не требуется.

## Открыть Codex с Windows

Откройте PowerShell или Windows Terminal и выполните:

```powershell
python C:\git\Srv\srv.py connect --host SERVER_IP
```

Скрипт подключится по SSH-ключу и вернёт в существующую сессию tmux `codex`.
Если такой сессии нет, создаст её и запустит Codex.

Чтобы отключиться и оставить агента работать: нажмите **Ctrl+B**, отпустите,
затем нажмите **D**. Чтобы вернуться, повторите команду выше.
При обрыве SSH сессия также сохраняется. Перезагрузка сервера завершает tmux;
историю разговора после неё можно открыть через `codex resume`.

На Ubuntu-клиенте из каталога проекта:

```bash
python3 srv.py connect --host SERVER_IP
```

Клиенту нужны Python 3.9+ и OpenSSH. На другом компьютере потребуется собственный
SSH-ключ, добавленный в `authorized_keys` рабочего пользователя; одного копирования
скриптов недостаточно. Личная авторизация Codex хранится на сервере.

## Прокрутка в Windows Terminal и tmux

Обёртки `srv-session` и `srv-session-claude` включают `mouse on` при каждом
подключении. Колёсико прокручивает историю tmux, в том числе в существующей сессии.
Клавиатурой: **Ctrl+B**, отпустить, затем **[**; листать **PageUp / PageDown**,
выйти из просмотра — **Esc**.

Если сервер установлен старой версией Srv, один раз обновите обёртку с Windows:

```powershell
python C:\git\Srv\srv.py agent-install --host SERVER_IP
python C:\git\Srv\srv.py connect --host SERVER_IP
```

Работающий Codex сохраняется. Для Claude добавьте `--agent claude` к обеим командам.

Сразу включить колёсико в текущем tmux: **Ctrl+B**, затем **:**, ввести
`set -g mouse on` и нажать **Enter**. При ручном запуске tmux без обёртки
добавьте строку `set -g mouse on` в `~/.tmux.conf` на сервере.

## Открыть обычную консоль сервера

В PowerShell на текущем компьютере:

```powershell
ssh -p 22 -i "ПУТЬ_К_SSH_КЛЮЧУ" -o IdentitiesOnly=yes ai-agent@SERVER_IP
```

Уже внутри сервера:

```bash
tmux ls                       # список сессий
~/.local/bin/srv-session       # войти в Codex или создать сессию
# Либо только присоединиться к уже существующей:
tmux attach-session -t codex
```

Если внутри tmux видна командная строка после выхода из Codex, запустите
`~/.local/bin/srv-codex resume` для выбора сохранённого разговора или
`~/.local/bin/srv-codex` для обычного запуска.
Для выхода из обычной SSH-консоли используйте `exit`; для сохранения работающей
сессии агента используйте отсоединение **Ctrl+B**, затем **D**.

Root нужен для администрирования. В той же команде SSH замените
`ai-agent@SERVER_IP` на `root@SERVER_IP`.

### Сеть для Git внутри Codex

Обёртка запускает Codex с `--sandbox workspace-write` и
`-c sandbox_workspace_write.network_access=true`: изменения файлов ограничены
рабочей областью, исходящие сетевые соединения разрешены.
Для уже установленной старой обёртки запустите от пользователя `ai-agent`,
без sudo и вне Codex:

```bash
bash /home/ai-agent/workspaces/live/FOLDER_ID/remote/enable-codex-network.sh
```

Скрипт сохраняет резервную копию `~/.local/bin/srv-codex` и обновляет команду
запуска. Завершите текущий Codex командой `/quit`, затем выполните в той же
tmux-консоли `~/.local/bin/srv-codex resume --last`.
Повторный `srv.py connect` сам по себе только подключается к существующему
процессу и не меняет его сетевые разрешения.

## Доступ к выбранной папке с сервера

Файловый мост запускается в отдельном терминале Windows:

```powershell
python C:\git\Srv\srv.py files-add --host SERVER_IP --folder C:\git\Srv --mode both --read-write --watch
```

В примере экспортируется каталог комплекта; замените `--folder` нужной папкой.
`FOLDER_ID` в таблице — вычисляемый идентификатор папки. Точные пути показывает
`files-add`; их также можно получить через `guide --host SERVER_IP --folder ПУТЬ`.

Если терминал файлового моста уже работает, оставьте его открытым: второй экземпляр
для той же папки не нужен. На сервере доступны:

| Путь | Что это |
|---|---|
| `/home/ai-agent/workspaces/live/FOLDER_ID` | Прямое чтение и запись в папку Windows, пока работает мост и соединение |
| `/home/ai-agent/workspaces/sync/FOLDER_ID` | Копия на сервере; изменения передаются в обе стороны, пока работает синхронизация |

Сообщите агенту нужный полный путь. Для работы во время отключения клиентского
компьютера используйте серверную копию. После восстановления связи изменения
синхронизируются; конфликтующие изменения требуют разбора, удаления автоматически
не распространяются. Служебные каталоги и `.git` исключены из передачи;
репозитории для Git-операций клонируйте отдельно на сервере.

Остановить мост можно через **Ctrl+C** в его терминале или из другого терминала:

```powershell
python C:\git\Srv\srv.py files-stop --host SERVER_IP --folder C:\git\Srv
```

Серверная копия после остановки остаётся. Перед первой передачей большого каталога
скрипт оценивает время и запрашивает подтверждение, если оценка превышает две минуты.

## Другой сервер, порт или агент

```powershell
python C:\git\Srv\srv.py connect --host SERVER_IP --port 2222 --user ai-agent --agent codex
```

Порт по умолчанию `22`, пользователь `ai-agent`, агент `codex`.
Для Claude используется `--agent claude`, если он предварительно установлен
и авторизован. Свой SSH-ключ можно указать через `--identity ПУТЬ_К_КЛЮЧУ`.

Первичное развёртывание описано в [README.md](README.md).
Ручная установка и восстановление — в [docs/RUNBOOK.md](docs/RUNBOOK.md).
